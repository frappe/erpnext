E.R.I.K - Human Resource & Payroll Summary / ScopeERIK’s HR & Payroll subsystem must support the full employee lifecycle and payroll operations for multi-company, multi-branch clients. It must be modular (individual modules can be enabled per client), Smart-Invoice/OCR aware where relevant, support TPIN/tax validation, multi-currency payroll, role-based access, audit trails, export to accounting, and both a Python frontend (Streamlit / Replit-ready) and a FastAPI backend. Everything should be secure, auditable, and configurable to local compliance (Zambia) with the ability to adapt to other jurisdictions.High-level modules (priority + short description)Use these as separate code modules/services (microservices or modules within a monolith).1. Job Requisition & Approval Workflowo Create, approve, track job requisitions; link to budgets and positions.2. User Role & Permission Matrix Managero Admin UI for roles, permissions, scopes (company/branch/department), and enforced role checks.3. Audit Trail Viewer & Access Control Logso Immutable logs for all HR/payroll actions. Exportable, searchable by user / date / action.4. Promotion, Demotion & Transfer Trackero Track personnel moves, effective dates, approvals, and salary adjustments.5. Employment Contract Managemento Store contract templates, signed contracts (file storage), auto-generate contract letters.6. HR Letters & Document Generatoro Generate appointment, confirmation, termination, NOC, salary verification letters (PDF/Word).7. HR Analytics & Workforce Insights Dashboardo Headcount, turnover rate, FTE, leave balances, gender split, cost by department.8. HR Budgeting & Forecasting Engineo Department-level salary budget planning, headcount plans, salary increase modeling.9. HR Cost Allocation & Departmental Spend Trackero Allocate payroll costs to departments/projects; integrate to GL.10. (User requested) HR & Payroll Moduleo The primary payroll engine: payslips, taxes, statutory deductions, salary advances, loans.11. Loans & Salary Advances Managemento Requests, approval, amortization schedules, integration to payroll for deductions.12. Skills & Competency Trackero Employee skill records, training history, certification expiries.13. (Other HR operations)o Onboarding/offboarding automation, background checks, equipment assignment.14. (Procurement/Smart Invoice/OCR)o Integrations where payroll interacts with procurement (e.g., petty cash, staff purchases, vendor payments) or when OCR affects invoices for contractor payments.15. Petty Cash Request & Float Managemento Staff petty cash requests (for payroll/HR petty expenses), approval and reconciliation.Non-functional requirements Backend: FastAPI (Python) — consistent with project context. Use Pydantic models, OpenAPI docs, and JWT + RBAC middleware. Frontend: Two formats for each feature:o HTML/CSS/JS (vanilla or React) for public web UI.o Python frontends (Streamlit) for internal admin tools / demos — deployable on Replit/Render/Heroku/Vercel. DB: PostgreSQL (production) with support for JSONB for flexible configs; optionally use Redis for caching. Migrations via Alembic. File storage: S3-compatible (minio) or cloud provider; store signed contracts, payslips (PDF) and scanned IDs. Security: TLS, password hashing (bcrypt/argon2), rate limiting, audit logs, encryption-at-rest for sensitive fields (IDs, bank details). Internationalization: Multi-currency support; date/time localized to Africa/Lusaka by default. Testing: Unit, integration, and end-to-end tests. CI pipeline (GitHub Actions). Observability: Structured logs, metrics, and error tracking (Sentry).Data model (core tables / models)I’ll present simplified SQL-like schemas. deductions (PAYE/similar, social security, loans, advances, pension). Configurable salary components defined per company; formula engine supports:o Fixed amountso Percent of baseo Conditional formulas (e.g., overtime = hours * rate)o JSON representation and a safe formula evaluator Tax engine: modular tax plug-ins per jurisdiction. For Zambia: TPIN validation (see integrations). Tax brackets defined via tax_settings. Provide employer/employee split for statutory contributions. Multi-currency: calculate components in employee home currency. Store exchange rate used per payrun (source: company rates or manual). Round handling configurable. Salary advances & loans: amortization schedules; integrate with payroll to deduct agreed amounts; track outstanding balance and interest. Payslip generation: HTML -> Archive. Edge cases: Retroactive pays (back pay), off-cycle payments, terminations and final settlements, statutory leave pay.API design (example endpoints — use REST + OpenAPI)All endpoints Use a safe expression evaluator (asteval or build AST with limited functions). Rounding: floating-point rounding must be predictable (use decimal libraries). Back pay and retro adjustments: design payrun with adjustments and retro-pays as separate line items. Privacy: obey data retention and allow export/deletion workflows; but ensure payroll legal retention is considered. Performance: bulk payrun computations should be batched and use worker queues (Celery) for large client runs. Migration path: ensure ability to import legacy employee/payroll data via CSV templates.Example acceptance tests (short)1.
